# Routing table

Which of the catalogued `.claude/skills/*` to run against a changed file,
keyed off path globs. Derived from the `Scope` column in
`.claude/skills/README.md` and the module map in root `CLAUDE.md`. Update
this table when a skill is added to, removed from, or rescoped in that
catalog — it is the only place file→skill routing is defined.

`**/vendor/**` and `server/clones/**` are never routed to a skill for
style review — see "Do-not-touch paths" below instead.

| Skill | Applies when the diff touches |
|---|---|
| `onion-architecture` | `server/src/**`, `reviewer-core/src/**` |
| `fastify-best-practices` | `server/src/modules/*/routes.ts`, `server/src/app.ts`, `server/src/platform/**` |
| `drizzle-orm-patterns` | `server/src/db/**`, `server/src/modules/*/repository*` |
| `postgresql-table-design` | `server/src/db/schema*`, `server/src/db/migrations/**` |
| `frontend-architecture` | `client/src/**` |
| `next-best-practices` | `client/src/app/**`, `client/next.config.*` |
| `react-best-practices` | `client/src/**/*.tsx` |
| `react-testing-library` | `client/**/*.test.{ts,tsx}`, `client/**/*.spec.{ts,tsx}` |
| `zod` | any `**/*.{ts,tsx}` — only when the hunk itself defines/edits a `z.object`/schema, not just any TS file |
| `typescript-expert` | any `**/*.{ts,tsx}` across `server/`, `client/`, `reviewer-core/`, `e2e/` |
| `security` | any changed file — auth, input handling, uploads, and secrets can appear in any package |

`mermaid-diagram` is not in this table. It is a diagram-authoring skill,
not a code-review skill, and has nothing to say about a diff.

## Matching rule

1. Build the changed-file list from the diff (see `SKILL.md` step 1).
2. Drop do-not-touch paths first (below) — they're a finding on their own,
   not routed further.
3. For each remaining file, collect every row above whose glob matches.
   A single file commonly matches more than one skill (e.g. a
   `client/src/app/foo/page.tsx` matches `frontend-architecture`,
   `next-best-practices`, `react-best-practices`, `typescript-expert`,
   `security`).
4. The result is a **skill → file-list** map. A skill with an empty file
   list is not run. Skip the whole step if the map is empty (e.g. a diff
   touching only `*.md`/`*.json` outside the tables above).

## Do-not-touch paths (from root `CLAUDE.md`)

If the diff touches any of these, it is reported directly as a finding —
severity CRITICAL, category "do-not-touch" — instead of being routed to a
skill:

- `server/clones/**` — git-ignored checkouts, regenerated by the app.
- `*/src/vendor/**` — vendored packages; edit at the source, not here.
