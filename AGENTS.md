# DevDigest

Local-first AI PR review — course starter. Full picture → README.md.

## Stack
Node ≥22 · pnpm ≥10 · Docker (Postgres/pgvector).
NOT a monorepo — 4 standalone packages, own package.json/lockfile each,
cross-package sharing via tsconfig path aliases (not published modules).

## Build/test
`./scripts/dev.sh` — boots everything from zero (see README Quick start).
Per-package: `pnpm dev` / `pnpm test` / `pnpm typecheck` (run from that package's dir).

## Non-default conventions
- Secrets (API keys, GITHUB_TOKEN) live in `~/.devdigest/secrets.json` (0600) —
  never in .env/git/DB. `process.env` is only the fallback.
- Migrations are NOT applied on boot — `cd server && pnpm db:migrate` manually.
- Agent instructions live in `AGENTS.md`; each module's `CLAUDE.md` is a
  git-tracked symlink to the `AGENTS.md` next to it (Claude Code only reads
  `CLAUDE.md`). Edit `AGENTS.md` — never replace the symlink with a copy.

## Do not touch
- `server/clones/` — git-ignored checkouts of imported repos, regenerated by the app.
- `*/src/vendor/**` — vendored packages (ui, shared); edit at the source, not here.

## Read when
- `docs/agent-prompts/` — read when touching built-in agent system prompts.
- `<module>/AGENTS.md` — auto-loads (via the `CLAUDE.md` symlink) when you touch files inside that module; don't duplicate its content here.
- `<module>/README.md` — read when you need that module's architecture/flow diagrams.
- `<module>/specs/` — read when implementing against a written feature spec.
- Reading is mandatory: the moment a request names or implies a module, use
  the `engineering-insights` skill to read that module's `INSIGHTS.md` before
  responding — not just before editing code. Treat it as high-confidence
  guidance.
- Writing is conditional: at the end of a non-trivial task, run
  `engineering-insights` to check whether the finding is already recorded and,
  if not, add it to `<module>/INSIGHTS.md`. Write nothing when the session
  produced nothing substantial, or when the file already covers it.
